# Telos / Phylax Restoration Errata — 2026-09-10

**Status:** canonical correction record. Preserve prior commits and historical
writeups as provenance; apply this errata to current architecture, code, and
migration decisions.

## E1 — the 2026-08-29 ownership design was never superseded

The accepted 2026-08-29 design remains canonical:

- Telos owns **all endpoint-specific security**;
- Phylax owns generic security/safety admission and runtime-check machinery;
- Oramasys owns application/workflow/routing policy;
- provider owners own provider protocol/lifecycle semantics;
- Agate owns hardware capability/placement evidence;
- Core owns irreducible execution mechanics.

The later semantic-only Telos scaffold was implementation drift, not an
architecture replacement.

## E2 — Telos inherits the full Tripwire authority

Telos succeeds the original Tripwire concept and owns the complete reusable v2
endpoint-security path:

1. endpoint parsing and canonical identity;
2. IP/CIDR/special-use and metadata classification;
3. SSRF policy;
4. DNS resolution and rebinding/TOCTOU defense;
5. connection-time pinning and peer verification;
6. redirect revalidation;
7. proxy isolation;
8. TLS destination identity, Host, and SNI preservation;
9. purpose-scoped semantic endpoint-use authorization.

Semantic permission and transport safety remain separate decisions **inside the
same Telos authority**.

## E3 — caller-supplied public/private classification is invalid

The September scaffold placed `is_public` on `EndpointRef` as caller-supplied
trusted evidence. That boundary is superseded. Telos now derives destination
classification from its own resolution evidence and produces `EndpointIdentity`.
Consumers must not assert public/private status to authorize themselves.

## E4 — Telos and Phylax use Apache-2.0

The initial MIT scaffolds were incorrect governance choices. Telos and Phylax
use Apache License 2.0, matching the independently packaged PT endpoint-policy
authority whose behavior Telos replaces in v2. This correction does not change
the MIT policy for `oramasys/oramasys` or `oramasys/perpetua-core`.

## E5 — clean-room means no v2 runtime dependency on PT

PT v1 remains an independent legacy authority in its own regime. Its endpoint
policy, SSRF checks, pinned adapter, tests, and `.agent` decisions are golden
behavior/provenance evidence only. Telos must not import, shell out to, locate,
or otherwise depend on PT at runtime.

## E6 — Claude-Desktop-LLM is a consumer, not a second authority

The former `src/policy/endpoint-policy.ts` implementation is valuable parity
evidence. Its reusable endpoint-security behavior belongs in Telos. The
steady-state Claude implementation keeps only a provider-facing compatibility
facade and delegates the actual request through the language-neutral Telos
bridge. There is no direct-fetch fallback.

Current transfer evidence: `oramasys/Claude-Desktop-LLM` PR #1.

## E7 — the Oramasys Gateway dialer is transitional evidence

`oramasys/oramasys/src/orama/gateway/dialer.py` was implemented under the
semantic-only Telos split and currently duplicates DNS resolution, address
classification, and connector security. Those behaviors are useful parity
vectors, including CGNAT, 6to4 relay anycast, Teredo, 6to4, all-answer
validation, and bounded timeouts, but the module must not remain a competing
endpoint-security authority.

Oramasys may retain application/provider-specific purpose and port policy. The
DNS/classification/socket-pinning mechanism must migrate to the restored Telos
contract. A blind Telos dependency-SHA bump is not sufficient because the
Gateway still consumes the superseded `EndpointRef.is_public` contract.

## E8 — Phylax explicitly excludes endpoint-specific security

Phylax may provide generic admission, provenance/integrity checks, redaction,
security/safety policy packs, and monitorability/runtime-check machinery. It
must not implement URL parsing, SSRF, DNS resolution, address classification,
pinning, redirects, proxy isolation, TLS destination identity, or endpoint-use
semantics. Those are Telos concerns.

Current boundary/license correction evidence: `oramasys/phylax` PR #1.

## E9 — project coverage floor is 80 percent

Every project maintains at least **80% test coverage** unless a component
already defines a stricter threshold. A stricter threshold is binding and must
never be lowered. Risk-based test selection remains valid for local iteration,
but completion evidence must satisfy the project/component coverage contract.

Telos restoration verification before publication: 28 passing tests, 91.29%
line coverage.

## E10 — citation contamination cannot establish repository facts

The Telos/Phylax evolution writeup referred to as “Document 7” used unrelated
external citations as if they established private repository facts. It is
therefore untrusted secondary synthesis until each architecture claim is
re-grounded in repository files, commits, PRs, PT `.agent` evidence, or explicit
owner-approved decisions.

Do not invent its author, date, or generating tool. Unknown provenance remains
unknown until the actual artifact metadata is located.

## E11 — evidence precedence

When sources conflict, use this order:

1. explicit owner-approved architecture decisions and this correction record;
2. current tested successor implementation and exact commit/PR evidence;
3. canonical Orama migration/ADR documents as corrected by explicit errata;
4. PT `.agent` decisions and v1 implementation as historical/parity evidence;
5. preserved historical plans and writeups;
6. external/background sources only for genuinely external facts, never to
   fabricate support for repository-specific claims.
